# BiliMusicApi 配置文件说明

⚠️ **重要**：API 启用需要同时满足以下条件：
- `serveUrl` 必须填写（无默认值）
- `ffmpeg` 必须可用（配置路径或系统 PATH）
- **缓存目录必须存在且可写**（API 不会在无权限时启动）

---

## 📄 配置文件示例

```json
{
  "cacheDir": "music_cache",
  "serveUrl": "http://localhost:8090/",
  "ffmpegPath": "ffmpeg",
  "maxAudioLength": 45,
  "maxCacheSize": 100,
  "quality": 6,
  "advanced": {
    "maxRetry": 3,
    "retryDelay": 1500,
    "userAgent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"
  }
}
```

---

## 📋 字段详解

### 1. 必填项（缺失或错误将导致 API 禁用）

| 字段名      | 类型   | 说明                                                                                                                                 |
|-------------|--------|--------------------------------------------------------------------------------------------------------------------------------------|
| `serveUrl`  | 字符串 | 外部 HTTP 服务器提供音频文件的访问地址，**必须以 `/` 结尾**。例如 `http://example.com/music/`。**无默认值**，必须配置。               |
| `cacheDir`  | 字符串 | 音频缓存目录。默认为 `"music_cache"`（相对于服务端根目录）。API 会检查该目录**是否存在、是否为目录、是否可写**，不满足条件则禁用。       |

### 2. 可选顶层配置

| 字段名             | 类型    | 默认值  | 说明                                                                                                                            |
|--------------------|---------|---------|---------------------------------------------------------------------------------------------------------------------------------|
| `ffmpegPath`       | 字符串  | `"ffmpeg"` | ffmpeg 可执行文件路径。若不在 PATH 中，请填写绝对路径（如 `C:/ffmpeg/bin/ffmpeg.exe`）。若路径无效，API 尝试使用系统 PATH 中的 `ffmpeg`。 |
| `maxAudioLength`   | 整数    | `45`    | 允许播放的最大视频时长，**单位：分钟**。设为 `0` 表示不限制。若为负数自动回退 `45`。                                      |
| `maxCacheSize`     | 整数    | `100`   | 缓存目录最大总大小，**单位：MB**。设为 `0` 表示不限制。若为负数自动回退 `100`。**仅在启动/重载时清理一次**。    |
| `quality`          | 整数    | `6`     | ffmpeg `-q:a` 参数，取值范围 `0` ~ `9`，数值越低音质越高（文件越大）。若缺失或超出范围，回退 `6`，不影响 API 启用。 |

### 3. `advanced` 高级选项（可选）

| 字段名        | 类型    | 默认值                                                                                                     | 说明                                                                                                                    |
|---------------|---------|------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------|
| `maxRetry`    | 整数    | `3`                                                                                                        | 搜索请求失败时的最大重试次数。设为 `0` 或负数表示不重试。                                            |
| `retryDelay`  | 整数    | `1500`                                                                                                     | 每次重试间隔，**单位：毫秒**。设为 `0` 或负数表示不等待。                                    |
| `userAgent`   | 字符串  | `"Mozilla/5.0 ... Chrome/120.0.0.0 Safari/537.36"`                                                         | 请求 B站 API 时的 User-Agent。一般无需修改。                                              |

---

## ⚙️ 配置生效与启动条件

- 修改 `bili.json` 后，执行 `/music reload` 或重启服务器，API 重新加载。
- 若配置文件损坏（JSON 格式错误），自动备份并生成默认配置，API 禁用。
- **API 启用条件**（三者缺一不可）：
  1. `serveUrl` 已填写且非空。
  2. `ffmpeg` 可执行（`ffmpeg -version` 成功）。
  3. `cacheDir` 指向的目录**存在、为目录且可写**（若不存在，API 会尝试创建；创建失败或不可写则禁用）。

## 🚨 常见问题与日志解读

### 缓存目录问题

| 日志内容 | 含义 | 解决 |
|---------|------|------|
| `缓存目录不可用：<路径>（可能不可写或不是目录）` | 路径不是目录或权限不足 | 检查路径是否正确，确保目录存在且服务进程有写入权限 |
| `缓存目录不存在，尝试创建` | 目录不存在，API 尝试创建 | 若创建失败，检查上级目录权限 |
| `创建缓存目录失败：<路径> - <异常>` | 创建失败（如无权限、路径非法） | 手动创建目录并赋予写权限，或修改 `cacheDir` 为有效路径 |
| `缓存目录没有写入权限：<路径>` | 目录存在但不可写 | 修改目录权限（如 `chmod 755`） |

### ffmpeg 问题

| 日志内容 | 含义 | 解决 |
|---------|------|------|
| `ffmpeg 文件不存在：<路径>` | 配置的绝对路径无效 | 填写正确路径或移除配置使用系统 PATH |
| `ffmpeg 执行失败，退出码：<码>` | ffmpeg 启动失败 | 检查 ffmpeg 依赖库、权限或路径 |
| `系统 ffmpeg 可用，将使用它` | 配置路径无效但系统 PATH 中有 ffmpeg | 建议在配置中明确指定路径以避免不确定性 |

---

## 🔧 目录权限检查说明

每次 `reload` 都会执行以下检查：
- 若 `cacheDir` 不存在 → 尝试创建（含父目录）。
- 若存在 → 验证是否为目录，并测试写入权限（`Files.isWritable()`）。
- 若任何一步失败，API 禁用并输出明确错误日志。
